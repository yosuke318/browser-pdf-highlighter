# 賃貸の入居申込書

賃貸物件の入居審査で、申込者が書く書類。**決まった様式がない**のが最大の特徴で、
管理会社・仲介会社・家賃保証会社ごとに独自の様式を使う。座標領域指定は様式ごとに
しか効かないので、ラベル近傍探索を主に使う。

## 書類の特徴

- タイトルの例: 「入居申込書」「賃貸借契約申込書」「入居申込書兼審査依頼書」
  「賃貸住宅入居申込書」。家賃保証会社の申込書と一体になっていることも多い
- 手書きで記入され、仲介会社からFAXで届くことが多い。テキストレイヤーがない
  スキャンPDFが前提で、OCRの精度も低くなりやすい(`samples/` のダミーも
  手書き・FAXの想定)
- 1枚に「申込者(契約者)」「入居者」「連帯保証人」「緊急連絡先」の欄が並ぶ。
  同じ「氏名」「勤務先」のラベルが何度も出るので、見出しで領域を分けてから探す

## 抽出項目

キー名は `scripts/generate-samples/templates/rental-application.ts` の
`expected` に合わせている。申込者は `applicant`、連帯保証人は `guarantor` の下に入れる。

| キー | 欄の名前(表記ゆれ) | 型 | 注意 |
|---|---|---|---|
| `appliedOn` | 申込日、申込年月日 | date | 和暦が多い |
| `propertyName` | 物件名、建物名、マンション名 | text | |
| `room` | 号室、部屋番号 | text | 「201号室」の「号室」は除く |
| `rent` | 賃料、家賃、月額賃料 | money | 管理費・共益費と別の欄。合算しない |
| `*.name` | 氏名、お名前、契約者名 | text | フリガナ欄と区別する |
| `*.birthDate` | 生年月日 | date | 和暦と年齢が併記されることが多い |
| `*.age` | 年齢、満○歳 | number | 生年月日から計算した値と照合できる |
| `*.address` | 現住所、住所 | text | |
| `*.employerName` | 勤務先、勤務先名、会社名、勤務先(学校名) | text | 学生は学校名が入る |
| `*.yearsOfService` | 勤続年数、勤続 | number(年) | 欄がなく「入社年月」だけの様式もある |
| `*.annualIncome` | 税込年収、年収、年間収入、前年年収、年収(税込) | money | 「万円」単位が多い |
| `guarantor.relationship` | 続柄、申込者との関係 | text | |

## 読み違えやすい点

- **連帯保証人と緊急連絡先。** どちらも申込者以外の人の氏名・続柄・電話番号の欄で、
  見た目が似ている。連帯保証人は勤務先・年収の欄まであり、緊急連絡先は連絡先だけの
  ことが多い。見出しの文言で区別し、緊急連絡先の人を保証人として抽出しない
- **申込者と入居者。** 法人契約や親名義の契約では、申込者(契約者)と実際の入居者が
  別人になる。審査で見る年収は契約者のもの
- **年収の単位。** 「税込年収 420 万円」のように万円単位で書かれることが多いが、
  「4,200,000円」と円で書く人もいる。欄の単位表記を見て換算し、単位がない場合は
  桁数から判断せず低い信頼度にする
- **年収の種類。** 「税込年収」が普通だが、「手取り年収」「月収」を書かせる様式もある。
  月収しかない場合は年収に換算せず、別の項目として扱う
- **勤続年数と入社年月。** 勤続年数の欄がない様式では、入社年月から申込日までの
  年数を計算できるが、計算した値は抽出値と区別する(元の欄にない値を作らない)
- **年齢と生年月日の不一致。** 手書きでは年齢の書き間違いが多い。生年月日から
  計算した満年齢と合わない場合は、差異として表示する

## 審査でよく見る観点(参考)

画面の強調表示や差分の重要度を決めるときの参考。審査基準そのものは管理会社や
家賃保証会社ごとに違うので、アプリ側で合否を判定しない。

- 家賃と年収の釣り合い: 「家賃は月収の3分の1以内」(年収が家賃の36倍以上)が
  業界でよく使われる目安
- 勤続年数: 短い(1年未満など)と追加の確認書類を求められやすい
- 連帯保証人の年収と続柄: 親族で、安定した収入があるか
- 前回の申込書との差: 年収や勤務先が変わっていないか(このアプリの差分検出の主な用途)
