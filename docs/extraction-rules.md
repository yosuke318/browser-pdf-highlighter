# 書類定義(抽出ルール)の書き方

書類タイプごとの抽出ルールは `src/extract/definitions/<書類ID>.ts` に書く。
ファイルを置くだけで抽出の対象になり、リグレッションテストでダミーPDFの正解データと自動で突き合わせられる。

- 書類IDと項目のキーは、抽出項目の定義(`schema/extraction-fields.json`)に合わせる。合っていないとテストが失敗する
- 項目の型(日付・金額など)は抽出項目の定義から決まるので、ルールには書かない。取った文字列は型に合わせて変換し、変換できない候補は使わない
- ルールを書いていない項目や、どのルールでも取れなかった項目は「未検出」になる。推測で埋めない

## 例

```ts
import { defineDocument } from "../rules.ts";

export default defineDocument({
  id: "withholding-slip",
  keywords: ["給与所得の源泉徴収票"],
  fields: {
    // 「令和7年分」を、行の文字列から正規表現で取る
    incomeYear: [{ kind: "pattern", pattern: /((?:令和|平成)\d+年)分/ }],
    // 「支払金額」の下にある金額を取る。左上の「内」は金額ではないので自動で飛ばす
    paymentAmount: [{ kind: "label", labels: ["支払金額"], direction: "below" }],
    // 上のルールで取れなければ、下のルールを試す
    name: [
      { kind: "label", labels: ["氏名"], direction: "below", reject: /フリガナ/ },
      { kind: "label", labels: ["受給者氏名"], direction: "right" },
    ],
  },
});
```

## ルールの種類

| kind | 取り方 | 主な設定 |
|---|---|---|
| `label` | 欄の名前(ラベル)を探し、その右または下にある値を取る | `labels`(表記ゆれ)、`direction`(`"right"` / `"below"`、配列なら順に試す)、`maxDistance`(ラベルの文字の高さの何倍まで離れてよいか。既定は右 25、下 5)、`maxCells`(値が何個のセルに分かれていてよいか。既定 6)、`inline`(ラベルで始まるセルの続きを値にするか) |
| `pattern` | 1行の文字列(同じ高さのセルをつなげて正規化したもの)から、正規表現で取る | `pattern`(値の部分を1番目のグループか `value` という名前のグループにする) |
| `region` | ページ上の範囲にある文字を取る | `rect`(ページの幅・高さに対する割合。原点は左上) |
| `derive` | ほかの項目の値から計算する | `from`(もとの項目のキー)、`compute`(計算する関数) |

`label` `pattern` `region` には、次の設定も付けられる:

- `section`: 探す範囲を、見出しで区切った範囲に限る(例: `{ start: ["申込者"], end: ["連帯保証人"] }`)。同じラベルが何度も出る様式(入居申込書の申込者欄と連帯保証人欄など)で使う
- `region`: 探す範囲を、ページ上の範囲に限る
- `accept` / `reject`: 値の候補(正規化した文字列)が正規表現に合うときだけ採用する / 採用しない
- `id`: ルールの名前。抽出結果に残る(なければ `label#1` のような名前になる)

## 値の選び方

- ルールは上から順に試し、最初に値が取れたルールを使う。2番目以降のルールで取れた値は、確からしさ(`confidence`)を少しずつ下げる
- 1つのルールの中では、前のページで見つかった値を優先し、同じページの中ではラベルに近い値を使う
- `label` で値が複数のセルに分かれているとき(「昭和」「63年」「4月」「15日」)は、型に合うまでセルをつなげる
- ラベルと値は、正規化(全角・半角、康熙部首、空白の違いをなくす)してから比べる
- 文字列の項目では、`inline` の既定は `false`。「氏名」と「氏名又は名称」のように、ラベルが別の欄の名前の先頭と一致することがあるため。金額・日付などの項目では、続きが型に合うかで判断できるので既定は `true`

## 抽出結果

項目ごとに `{ key, found, value, rawText, bbox, page, confidence, ruleId, source, warnings }` を返す(`src/extract/engine.ts` の `FieldResult`)。

- `bbox` は値の部分を囲む長方形(PDFページ座標)。値が複数のセルに分かれていれば、セルごとに並ぶ
- `rawText` は取り出したままの文字列。`value` は型に合わせて変換した値
- `warnings` は確認が必要な点(元号の期間外の日付、ほかの項目から計算した値など)

## 確かめ方

```bash
npm test                              # ルールの単体テストと、ダミーPDFでのリグレッションテスト
npx vitest run src/regression -u      # 抽出できる項目が増えたら、記録を更新する
```

新しい書類タイプを足すときは、`samples/` にダミーPDFと正解データも足す(`samples/README.md`)。
