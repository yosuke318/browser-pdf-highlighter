# 対象書類の様式調査

YOSUKE-193「01: Collect sample documents and confirm formats and issuers」の調査メモ。
抽出ルール(書類タイプ別の定義ファイル)を設計するための前提情報をまとめる。

- 調査日: 2026-10-12
- 前提: 扱うPDFは **すべて紙をスキャンしたもの**(利用者ヒアリングより)

---

## 0. 「テキストPDF」と「スキャンPDF」の違い

| | テキストPDF | スキャンPDF |
|---|---|---|
| 作られ方 | Word・会計ソフト・e-Tax・電子交付などからPDFを直接出力 | 紙を複合機/スキャナで読み取る |
| 中身 | 文字データ + 位置(座標)が入っている | ページごとの **画像1枚** だけ。文字データなし |
| 見分け方 | 文字をドラッグ選択できる / Cmd+Fで検索できる | 選択も検索もできない |
| このアプリでの扱い | pdf.js `getTextContent()` で文字と座標がそのまま取れる | **OCR(画像→文字認識)が必須**。座標もOCR結果から得る |

注意点:

- 複合機の設定によっては、スキャン時にOCRをかけて「透明テキスト付きPDF」(見た目は画像だが裏に文字が入っている)を作れる。実サンプルで文字選択できるか確認しておくとよい。ただしその文字の精度は複合機のOCR次第で、そのまま信用はできない。
- 元が電子交付のPDF(源泉徴収票・住民税通知など)でも、一度印刷してスキャンされた時点でスキャンPDFになる。

---

## 1. 書類タイプ別の様式一覧

### 1-1. 源泉徴収票(給与所得の源泉徴収票)

**どんな書類か**: 勤務先が「去年1年間にいくら給料を払い、いくら所得税を天引きしたか」を本人に渡す書類。毎年12月〜翌1月に配られる。会社員の年収証明として最も一般的。

| 項目 | 内容 |
|---|---|
| 発行元 | 勤務先(給与の支払者) |
| 様式 | **国税庁の法定様式で全国共通**。ただし印刷するのは各社の給与ソフトなので、フォント・罫線・余白は微妙に違う。用紙はA6程度の小さい横長が基本(A4に1〜4面付け、圧着ハガキもあり) |
| バリエーション | ・年分による改正: **令和7年分から「特定親族特別控除の額」欄などが追加**され欄配置が変化<br>・税務署提出用(マイナンバーあり)/受給者交付用(マイナンバーなし)<br>・手書きはほぼ無い(活字) |
| PDF種別 | 現状は全件スキャン想定。原本は紙 or 電子交付PDF |
| OCRの難しさ | 低〜中。活字・定型。ただし文字が小さく、A4に縮小スキャンされると潰れやすい |

主要ラベル文言(抽出のアンカー候補):

- タイトル: `給与所得の源泉徴収票`、`令和 年分`
- 年収: `支払金額`
- その他金額: `給与所得控除後の金額`(調整控除後)、`所得控除の額の合計額`、`源泉徴収税額`、`社会保険料等の金額`
- 勤務先: `支払者` 欄の `住所(居所)又は所在地` / `氏名又は名称`
- 本人: `支払を受ける者`、`住所又は居所`、`氏名`
- 生年月日: `受給者生年月日`(元号 + 年月日)
- 入退社: `中途就・退職`(`就職` / `退職` と年月日)

### 1-2. 所得証明書・課税証明書

**どんな書類か**: 市区町村が「この人の去年の所得はいくらで、住民税はいくら課税されたか」を証明する公的書類。役所の窓口やコンビニで本人が取る。勤務先が複数ある人・自営業者の所得もまとめて載るのが源泉徴収票との違い。

| 項目 | 内容 |
|---|---|
| 発行元 | 1月1日時点で住んでいた **市区町村**(約1,700団体) |
| 様式 | **自治体ごとにバラバラ**。名称も「課税証明書」「所得証明書」「所得・課税証明書」「市民税・県民税課税証明書」「非課税証明書」など様々。同じ自治体でも「全項目証明」(所得・控除の内訳あり)と簡易版(税額だけ等)がある |
| バリエーション | ・窓口交付版とコンビニ交付版でレイアウトが違う自治体あり<br>・**偽造防止の地紋入り用紙**: コピー/スキャンすると「複写」「COPY」等の文字が背景に浮き出る |
| PDF種別 | 全件スキャン想定(原本は紙のみ) |
| OCRの難しさ | 中〜高。活字だが **地紋が文字に重なりOCRを邪魔する**。公印も重なる |

主要ラベル文言:

- タイトル: `課税証明書` / `所得証明書` / `非課税証明書` + `令和 年度`
- 収入・所得: `給与収入`(`給与の収入金額`)、`給与所得`、`合計所得金額`、`総所得金額`(`総所得金額等`)
- 控除・税額: `所得控除額`(`所得控除合計`)、`課税標準額`、`市民税` `県民税`(`特別区民税` `都民税`)、`年税額`
- 本人: `住所`、`氏名`、`生年月日`(記載ありの自治体が多い)
- 証明文: `上記のとおり証明します` + 首長名 + 公印

**注意: 「年度」と「年分」のズレ** — `令和8年度` の証明書に載るのは **令和7年(2025年)1〜12月** の所得。源泉徴収票・確定申告書の「年分」とは1年ずれる。差分検出で年をそろえるときに必須の変換。

### 1-3. 住民税決定通知書

**どんな書類か**: 「今年度の住民税はいくら、毎月いくら天引きします」という市区町村からのお知らせ。中身は課税証明書とほぼ同じ情報(前年の収入・所得・控除・税額)なので、住宅ローンでは課税証明書の代わりに使われることが多い。

| 項目 | 内容 |
|---|---|
| 発行元 | 市区町村 |
| 種類 | ・**特別徴収**(会社員): 正式名「給与所得等に係る市町村民税・道府県民税 特別徴収税額の決定・変更通知書(納税義務者用)」。**毎年5〜6月に勤務先経由で配られる**。様式は総務省令(地方税法施行規則 第3号様式別表)がベースなので比較的そろっているが、印字業者・自治体で細部は違う<br>・**普通徴収**(自営業者・年金受給者など): 納付書とセットで自宅に届く。様式は自治体ごとにバラバラ |
| バリエーション | ・圧着ハガキ型 / A4・A5の封書型<br>・令和6年度から納税義務者用の電子交付が可能に(電子で受け取って印刷→スキャン、もあり得る)<br>・東京23区は `特別区民税・都民税`、その他は `市町村民税・道府県民税`(`市民税・県民税` 等)と税目名が変わる |
| PDF種別 | 全件スキャン想定 |
| OCRの難しさ | 中。活字だが文字が細かく欄が密。圧着ハガキは剥がし跡・折れが出やすい |

主要ラベル文言:

- タイトル: `特別徴収税額の決定・変更通知書` / `税額決定通知書` + `令和 年度`
- 収入・所得: `給与収入`、`給与所得`、`総所得金額`、`合計所得金額`
- 控除・税額: `所得控除額`、`課税標準額`、`税額控除額`、`年税額` / `特別徴収税額`、`月割額`
- 勤務先: `特別徴収義務者`(= 勤務先)の `所在地` / `名称`
- 本人: `納税義務者`、`住所`、`氏名`

### 1-4. 確定申告書(所得税及び復興特別所得税の確定申告書)

**どんな書類か**: 自営業者・副業がある人・医療費控除を受ける人などが、翌年2〜3月に税務署へ出す「去年の所得と税額はこれです」という自己申告書類。自営業者・個人事業主の年収証明として使われる(住宅ローンでは過去3年分を求められることが多い)。

| 項目 | 内容 |
|---|---|
| 発行元 | **本人が作成**して税務署に提出(様式自体は国税庁) |
| 様式 | 国税庁の全国共通様式。**第一表(収入・所得・税額のまとめ)と第二表(内訳)は全員必須**、必要に応じ第三表(分離課税)・第四表(損失)。令和4年分以降は旧「申告書A/B」が統合され1種類 |
| バリエーション | ・作り方: 国税庁「確定申告書等作成コーナー」や会計ソフトで作成して印刷(活字)/ 紙の様式に **手書き**<br>・年分による改正: **令和7年分で「特定親族特別控除」欄の追加・定額減税欄の削除があり、欄番号が振り直された**。番号(①②…)ではなくラベル文言でルールを書くべき<br>・提出の証拠: 紙提出の控えには従来「収受日付印」があったが、**令和7年1月から控えへの押印は廃止**。e-Tax提出なら「受信通知(メール詳細)」の印刷が添付されることが多い<br>・事業者は青色申告決算書/収支内訳書が添付されることも |
| PDF種別 | 全件スキャン想定(作成コーナー印刷 → スキャン、が多いと思われる) |
| OCRの難しさ | 中〜高。**金額が1桁ずつ枠(マス目)に入っている**ので、OCR結果を桁ごとにつなぎ直す処理が要る。手書きの場合は高 |

主要ラベル文言:

- タイトル: `令和 年分の所得税及び復興特別所得税の確定申告書`、`第一表` / `第二表`
- 収入: `収入金額等`(区分: `事業` `営業等` `不動産` `給与` `雑` `公的年金等` など)
- 所得: `所得金額等`、`合計`
- 控除・税額: `所得から差し引かれる金額`、`課税される所得金額`、`申告納税額`
- 本人: `住所`、`氏名`、`生年月日`、`職業`、`屋号・雅号`、`世帯主の氏名`
- 勤務先(第二表): `所得の内訳` 欄の `種目` / `給与などの支払者の「名称」` / `収入金額`

### 1-5. 住宅ローン申込書・審査書類

**どんな書類か**: 家を買う人が銀行に「これだけ借りたい」と申し込む書類。本人の勤務先・年収・ほかの借金・買う物件の情報を書く。審査は「事前審査(仮審査)」→「本審査」の2段階で、それぞれ申込書がある。添付書類として源泉徴収票・課税証明書・確定申告書などが付く(=1-1〜1-4の書類はここの添付としても来る)。

| 項目 | 内容 |
|---|---|
| 発行元 | **金融機関ごとの独自様式**(都銀・地銀・信金・ネット銀行・フラット35取扱機関など)。保証会社の書式が付くことも |
| 様式 | 共通様式なし。A4〜A3で数枚。申込書本体 + 個人信用情報の同意書 + 団体信用生命保険の告知書 などのセット |
| バリエーション | ・**手書き記入が多い**(枠付きの記入欄)<br>・事前審査はWeb入力化が進んでおり、Web画面の印刷/控えPDFのケースもある<br>・年収の単位が `万円` のことが多い(源泉徴収票は `円`) |
| PDF種別 | 全件スキャン想定 |
| OCRの難しさ | **高**。手書きの数字・氏名はtesseract.jsではまず読めない |

主要ラベル文言(銀行により異なるため代表例):

- タイトル: `住宅ローン借入申込書`、`事前審査申込書`、`仮審査申込書`、`借入申込書`
- 本人: `氏名`、`生年月日`、`年齢`、`現住所`、`家族構成`
- 勤務先: `勤務先名`、`所在地`、`業種`、`雇用形態`、`役職`、`勤続年数` / `入社年月`
- 年収: `年収`(`前年度税込年収`、`税込年収`)、単位 `万円`
- 既存借入: `他の借入`、`借入先`、`借入残高`、`年間返済額`、`借入目的`(自動車ローン・カードローン等)
- 物件: `物件所在地`、`物件価格` / `購入価格`、`借入希望額`、`借入期間`、`返済方法`
- その他: `連帯保証人` / `連帯債務者` / `ペアローン` の配偶者欄

### 1-6. 入居申込書(賃貸)

**どんな書類か**: 賃貸物件を借りたい人が管理会社・大家さんに出す申込書。これをもとに入居審査と家賃保証会社の審査が行われる。

| 項目 | 内容 |
|---|---|
| 発行元 | **管理会社・仲介会社・家賃保証会社ごとの独自様式**。全国共通様式なし |
| 様式 | A4またはA3で1〜2枚が多い。管理会社の申込書と保証会社の「保証委託申込書」が別紙の場合と、1枚にまとめた一体型がある |
| バリエーション | ・**ほぼ手書き**<br>・**FAXでやり取りされることが多く**、FAX受信→スキャンで画質がかなり劣化する<br>・最近はWeb申込システム経由もあり、その場合は活字の申込内容出力になる |
| PDF種別 | 全件スキャン想定 |
| OCRの難しさ | **最高**。手書き + FAX劣化 + 様式バラバラ |

主要ラベル文言(代表例):

- タイトル: `入居申込書`、`賃貸借申込書`、`保証委託申込書`
- 物件: `物件名`、`号室`、`賃料`
- 申込者: `氏名`(`フリガナ`)、`生年月日`、`年齢`、`現住所`、`電話番号`
- 勤務先: `勤務先`(`会社名`)、`所在地`、`業種`、`雇用形態`、`勤続年数` / `入社年月`
- 年収: `年収`(`税込年収`)、単位 `万円` / `円` 混在
- 保証人: `連帯保証人` 欄に申込者と同じ項目(氏名・生年月日・勤務先・年収・続柄)
- その他: `緊急連絡先`、`入居者`(同居人)

## 2. 一覧(まとめ)

| 書類 | 発行元 | 様式の統一度 | 記入 | PDF種別 | OCR難度 |
|---|---|---|---|---|---|
| 源泉徴収票 | 勤務先 | ◎ 国の法定様式 | 活字 | スキャン | 低〜中 |
| 所得証明書・課税証明書 | 市区町村 | × 自治体ごと | 活字(地紋あり) | スキャン | 中〜高 |
| 住民税決定通知書 | 市区町村(特徴は勤務先経由) | ○ 特徴は省令ベース / △ 普徴 | 活字 | スキャン | 中 |
| 確定申告書 | 本人(様式は国) | ◎ 国の様式 | 活字 or 手書き | スキャン | 中〜高 |
| 住宅ローン申込書・審査書類 | 金融機関ごと | × | 主に手書き | スキャン | 高 |
| 入居申込書 | 管理会社・保証会社ごと | × | 主に手書き(FAX) | スキャン | 最高 |

全書類共通で抽出ルールが対応すべきこと:

- **和暦**(`昭和` `平成` `令和`、略記 `S` `H` `R`、元号を○で囲む形式)→ 西暦変換
- **全角/半角数字の混在**、カンマ有無、`円` / `千円` / `万円` の単位違い
- **年度と年分のズレ**(住民税系は「年度」= 前年の所得)
- スキャン起因: 傾き、かすれ、FAX劣化、地紋・公印の重なり
- マイナンバーや一部項目が **黒塗り(マスク)** されていることがある

## 3. プロジェクト計画への影響(要相談)

1. **OCRをM1に前倒しすべき**
   現計画では M1 が pdf.js `getTextContent()`(テキストPDF前提)、OCR対応(#21 tesseract.js)は M3。全件スキャンなら M1 の抽出が実データで1件も動かないので、OCRを M1 の土台(#07 テキスト・座標抽出レイヤー)に組み込む必要がある。テキストPDFが来たらOCRを飛ばす、という順序が自然。

2. **手書き書類は自動抽出の対象から外す/範囲を絞る判断が必要**
   tesseract.js(Tesseract)は活字向けで、手書きはほぼ読めない。入居申込書・住宅ローン申込書は「ラベル位置だけOCRで見つけて、その横の手書き欄を **ハイライトして人が読む**(値は人が入力)」程度が現実的な線。差分検出もこの2種は人の入力値ベースになる。

3. **MVPは活字の定型書類から**
   源泉徴収票 → 住民税決定通知書(特徴) → 確定申告書(作成コーナー印刷) → 課税証明書 の順が、精度が出やすく効果も大きい。

4. **OCR精度は実物で計測してから判断**
   スキャン解像度(300dpi推奨)、傾き補正・二値化などの前処理で精度が大きく変わる。ダミーではなくマスク済み実サンプル数件で認識率を測るのが望ましい。

---

## 4. 当事者(利用者)に確認したいこと

- 各書類が月に何件くらい来るか(優先度付けのため)
- 入居申込書・住宅ローン申込書は、どの管理会社/保証会社/銀行の様式が多いか(上位数社分だけ定義ファイルを作る)
- 手書き書類の扱い: 「ハイライト + 手入力」で許容できるか
- スキャン設定(解像度・カラー/白黒・複合機のOCR機能の有無)を指定できるか
- マスク済みの実サンプルを各タイプ数件ずつ借りられるか
