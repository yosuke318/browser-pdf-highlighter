# 抽出項目と出力形式(案)

書類ごとに抽出する項目、前回資料との差分の判定ルール、結果の出力形式の **案**。
利用者と確認して合意版にする。確認したい点は最後の「6. 利用者に確認したいこと」にまとめた。

- 機械が読む定義: [`schema/extraction-fields.json`](../schema/extraction-fields.json)(この資料の表はここから作っている。食い違ったらJSONが正)
- ダミーPDFの正解データ(`samples/*/expected.json`)は、この定義と一致することを `npm run samples:check` で確認している

---

## 1. 共通の決まり

- **値の持ち方**
  - 金額は円単位の整数。「万円」「千円」の欄は円に換算する(「420万円」→ 4,200,000)
  - 日付は西暦の `YYYY-MM-DD`、年月は `YYYY-MM`、年は西暦4桁。和暦は変換する
  - 元の文字列(例: 「昭和63年4月15日」「420万円」)も残し、画面で並べて見せる
- **出どころを必ず残す。** どの書類の、何ページ目の、どの欄(位置)から取ったか。ハイライトと差分の根拠になる
- **年は「対象年(所得の年)」でそろえる。** 源泉徴収票・確定申告書の「令和7年分」と、課税証明書・住民税決定通知書の「令和8年度」は、どちらも2025年の所得。年度の書類は `fiscalYear`(年度)と `incomeYear`(対象年)の両方を持つ
- **収入と所得を混ぜない。** 収入は額面、所得は控除後。比較は同じ種類どうしで行う
- **人による確認が前提。** OCRで読んだ値や、自信のない値は「要確認」として表示する。読めない欄を推測で埋めない
- **必要以上の個人情報は取らない。** 電話番号・マイナンバー・緊急連絡先は抽出しない(画面上のPDFでは見える)

「必須」は、その書類なら通常書かれている項目。抽出できなかったときに「見つかりません」と注意を出す。
「差分で重視」(◎)は、差分の一覧で上に出し、目立たせる項目。

## 3. 書類をまたいだ比較

差分検出の主な用途は「同じ種類の書類の、前回と今回の比較」だが、同じ人の別の書類どうしで値が食い違っていないかも確かめられる。対応する項目は次のとおり。

| 比較する値 | 対応する項目 |
|---|---|
| 年収(額面) | 源泉徴収票「支払金額」/ 課税証明書・住民税決定通知書「給与収入」/ 確定申告書「給与収入」/ 住宅ローン申込書・入居申込書の自己申告の年収 |
| 所得の合計 | 課税証明書・住民税決定通知書「合計所得金額」/ 確定申告書「所得金額の合計」 |
| 勤務先 | 源泉徴収票 / 住民税決定通知書 / 住宅ローン申込書 / 入居申込書 |
| 生年月日 | 源泉徴収票 / 課税証明書 / 確定申告書 / 住宅ローン申込書 / 入居申込書 |

- 年収は書類によって信頼度が違う(目安: 市区町村の証明書 > 勤務先が出す源泉徴収票 > 本人の自己申告)。画面では値と一緒に出どころの書類名を出す
- 自己申告の年収は「万円」単位で丸められていることが多いので、源泉徴収票などと比べるときは1万円未満の差を「一致(丸めの差)」とする案
- 年収どうしを比べるのは、対象年が同じときだけ

## 4. 差分の判定ルール

### 何と何を比べるか

- 同じ種類の書類どうしで、項目ごとに比べる(例: 前回の入居申込書と今回の入居申込書)
- 前回資料は利用者が選ぶ。前回のPDF、または前回書き出した抽出結果(JSON、→ 5)を読み込む
- 対象年が違う書類(前年分と今年分の源泉徴収票など)も比べられる。その場合は結果の一番上に「対象年: 2024年 → 2025年」と出す
- 氏名・生年月日が違う場合は「別の人の書類の可能性があります」と警告し、比較は続ける

### 判定の種類

| 判定 | 意味 | 例 |
|---|---|---|
| 一致 | 正規化した値が同じで、元の文字列も同じ | |
| 表記の違い | 正規化すると同じだが、元の文字列が違う | 「(株)サンプル商事」と「株式会社サンプル商事」、「1-2-3」と「1丁目2番3号」 |
| 変更 | 正規化しても値が違う | 年収 5,800,000 → 6,100,000 |
| 追加 | 前回は空欄、今回は値がある | 連帯保証人の欄に記入が増えた |
| 削除 | 前回は値がある、今回は空欄 | 他の借入の行がなくなった |
| 比較できない | どちらかが読み取れなかった | OCRで読めなかった欄 |

- 「変更」「追加」「削除」は差分として目立たせる。「表記の違い」は控えめに表示する
- 「比較できない」は「変更」と区別し、PDFを目で確認するよう促す
- OCRで読んだ値で、まだ人が確認していないものは、判定に「要確認」を付ける

### 型ごとの比べ方

| 型 | 比べ方 |
|---|---|
| 文字列 | 正規化してから比べる(空白・全角半角・康熙部首・会社名の略記・住所の表記・異体字。詳細は `.claude/skills/japanese-real-estate-docs/references/normalization.md`) |
| 金額 | 円単位の整数で比べる。1円でも違えば「変更」とし、増減額と増減率を出す(例: +300,000円、+5.2%) |
| 日付・年月・年 | 西暦に変換した値で比べる |
| 数値(年数・年齢) | そのまま比べる。年齢は申込日が違えば変わって当然なので、生年月日が同じなら「一致(年齢は申込日の違いによるもの)」とする |
| 有無 | そのまま比べる |
| 表(他の借入) | 借入先と借入目的で行を対応付け、行ごとに「追加」「削除」「変更」を出す |

## 5. 出力形式

| 形式 | 内容 | 案 |
|---|---|---|
| 画面表示 | PDF上のハイライト + 抽出結果の一覧 + 差分の一覧 | 必須(最初の版に入れる) |
| JSONの書き出し | 抽出結果をファイルに保存。次回、前回資料として読み込める(PDFを読み直さずに差分を取れる) | 最初の版に入れる |
| 印刷 | ブラウザの印刷機能で、抽出結果と差分の一覧を印刷 | 最初の版に入れる |
| CSVの書き出し | 抽出結果を表計算ソフトで開ける形で保存 | 要望があれば追加 |
| ハイライト付きPDFの書き出し | ハイライトを書き込んだPDFを保存 | 後回し |

書き出したファイルには個人情報が入る。保存先は利用者の端末だけで、サーバーには送らない。

書き出すJSONの形(案):

```json
{
  "formatVersion": "0.1.0",
  "documentType": "withholding-slip",
  "fileName": "源泉徴収票_2025.pdf",
  "extractedAt": "2026-10-12T10:00:00+09:00",
  "fields": {
    "paymentAmount": {
      "value": 5800000,
      "rawText": "5,800,000",
      "page": 1,
      "bbox": [120.5, 640.2, 210.0, 652.8],
      "source": "ocr",
      "confidence": 0.86,
      "confirmed": true
    }
  }
}
```

- `bbox` はPDFページ上の位置(左下x, 左下y, 右上x, 右上y。単位はポイント)
- `source` は文字の取り方(`pdf`: テキストPDFから取得 / `ocr`: OCR)
- `confirmed` は人が画面で確認・修正したかどうか
- `source` が `manual` の項目は、抽出できず、人が画面で入力した値
- 人が画面で値を直した項目は `edited: true` を付け、もとの値(抽出した値)を `originalValue` に残す。見つからなかった項目(人も入力していない項目)は書き出さない
- 1つのPDFに複数の書類が含まれていれば、書類ごとに別のファイルに書き出す(ファイル名は「PDFのファイル名.書類ID.json」)
- 書き出し・読み込みの実装は `src/results/export.ts`

## 6. 利用者に確認したいこと

**抽出項目**
1. 各書類の項目に、過不足はないか(特に住宅ローン申込書・入居申込書は様式がばらばらなので、よく使う様式の項目を見せてもらいたい)
2. 確定申告書は第一表だけでよいか。第二表(所得の内訳・勤務先)や青色申告決算書も必要か
3. 住民税決定通知書は、会社員向け(特別徴収)だけでよいか。自営業者向け(普通徴収)も来るか
4. 入居申込書の「入居者」(契約者と別の人が住む場合)の情報は必要か

**差分**
5. 何と何を比べることが多いか(同じ申込者の申込書の再提出 / 前年と今年の源泉徴収票 / 申込書と源泉徴収票の食い違い)
6. 金額は1円でも違えば「変更」でよいか。自己申告の年収と源泉徴収票の比較は、1万円未満の差を一致とみなしてよいか
7. 「表記の違い」(会社名の略記・住所の書き方など)は表示したいか、隠したいか

**出力**
8. JSONの書き出し・印刷は必要か。CSVは必要か
9. 書き出したファイルを、どこに・どのくらいの期間保存する運用か(個人情報の扱いの社内規程との関係)
